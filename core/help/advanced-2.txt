
  THE BRIEF AND THE LEDGER
    --no-brief         launch with no brief on purpose (without it a missing brief
                       dies, naming the path it looked for and the nearest names);
                       a brief that IS found is still used
    hw ledger [<lane>] [--brief <path>|--task <t>] [--state <s>] [--json]
                       each brief as never-dispatched, in-progress or done, from
                       $WORK/.hw-ledger/<lane>.jsonl plus the run's done marker
    hw briefs archive <lane> [--apply]
                       move the lane's finished briefs to briefs/archive/<yyyy-mm>/
                       (plan only without --apply); an archived task does not launch
    hw briefs restore <lane> <task> | unarchive <lane> --manifest <file>
                       the way back, one brief or a whole manifest

  KEYCHAIN HANDLES
    --no-handle-check  skip the keychain-handle preflight
    hw handle <handle>...           does a keychain handle resolve?

  BITWARDEN SECRETS (brief frontmatter  secrets: [item, ...] — items of the folder agents)
    hw secret run <item>[.<field>] --as VAR [--item <item> --as VAR ...] -- <cmd...>
                                    the value reaches <cmd>'s environment only; never printed
    <cmd> | hw secret put <item>[.<field>] [--replace]
                                    store the value a PIPE on stdin carries (a hidden field when .<field>);
                                    never printed, never in argv; an existing one is refused without --replace
    hw secret check <item>...       present / absent, no value      hw secret status | ensure
    secret-unlock --setup             once, a person: the master password into the Keychain (a LaunchAgent unlocks from it)
    secret-unlock [--hours N|--lock]  an interactive unlock / lock

  THE ONE-SHOT ESCAPE
    hw human-boundary "<why>"       executor-only one-shot escape for a genuine
                                    money/third-party/irreversible/outward/priority
                                    decision; names why the ordinary exits do not apply

  SUITES
    hw suite <project> [--status|--dry-run] [--wait-ms N] -- <command...>
        Run one command at a time per lane, behind that lane's suite lock.
        Names the holder instead of waiting mutely, and breaks an
        ORPHANED lock on the first pass rather than waiting it out. NEVER kill a
        suite with `pkill -f`: that pattern matches every lane's run and every
        agent's, and it has already destroyed three complete runs. Kill by pid,
        or wait.

  CONSENT VERDICTS
    `hw consent` reports its own VERDICTS in the same one number space, which is
    why they are 9 and 10 rather than the 3/4 the first draft reached for:
    9   NOT ANSWERED. hw made no decision and executed nothing — the run
        declared `ask`, or the candidate is above the declared ceiling. The
        consent envelope is still open; relay it to your brainer. This is a
        decision, not a failure, and routing around it defeats the ceiling.
    10  the provider itself exited 9. The answer WAS submitted; 9 is reserved
        for "hw executed nothing", so the collision is remapped rather than
        left ambiguous. Every other provider status is relayed unchanged, and
        1 remains hw's own single refusal code.
